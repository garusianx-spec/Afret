# سیستم طراحی آفرت

## توکن‌های رنگ

همهٔ رنگ‌ها به‌صورت سه‌تایی کانال در `:root` تعریف شده‌اند
(`apps/web/src/app/globals.css`) تا Tailwind بتواند `<alpha-value>` را اعمال
کند و همان مقدار از CSS خام، متا تگ `theme-color` و پوستهٔ آفلاین هم خوانده
شود — بدون تکرار هیچ hex.

| نقش | توکن | مقدار |
| --- | --- | --- |
| اکسنت اصلی / برند | `primary` (و `brand`) | `#AA4C7A` |
| هاور، اکتیو، متن روی تینت | `primary-deep` | `#913D65` |
| کم‌رنگ‌ترین پس‌زمینه | `primary-50` | `#FDF5F8` |
| کارت نرم، بج تب فعال | `primary-100` | `#F9EBF1` |
| حاشیه و جداکننده | `primary-200` | `#EFD3E0` |
| هشدار و تأکید گرم | `coral` | `#E8763F` |
| پس‌زمینهٔ نرم هشدار | `coral-soft` | `#FFE8D3` |
| موفقیت / چک‌لیست | `mint` | `#48BB78` |
| پس‌زمینهٔ صفحه | `surface` | `#FAF7F9` |
| سطح کارت | `surface-card` | `#FFFFFF` |
| حاشیهٔ کارت | `surface-border` | `#F3E8EE` |
| تیتر | `ink` | `#2D2B3F` |
| متن بدنه | `ink-muted` | `#6B687E` |

### چرا primary همان رنگ لوگوست

تا پیش از این، رابط کاربری بنفش ملایم (`#9C88FF`) بود و لوگو آلویی — دو
خانوادهٔ رنگی که کنار هم مثل دو برند به نظر می‌رسیدند. حالا `primary` و
`brand` یک مقدارند و `--afrat-brand` صرفاً یک alias است.

### کنتراست

هر پله در برابر WCAG AA سنجیده شده:

| ترکیب | نسبت |
| --- | --- |
| سفید روی `primary` | ۵٫۲۲ |
| سفید روی `primary-deep` | ۶٫۸۶ |
| `primary` روی `surface` | ۴٫۹۰ |
| `primary-deep` روی `primary-100` | ۵٫۹۴ |
| `ink` روی `coral-soft` | ۱۱٫۶۰ |
| `ink` روی `coral` | ۴٫۶۴ |

برای **متن** روی پس‌زمینهٔ تینت‌دار از `primary-deep` استفاده کنید نه
`primary`: خودِ `primary` روی `primary-100` به ۴٫۵۲ می‌رسد — قبول می‌شود،
اما فاصله‌اش با حد مجاز آن‌قدر کم است که برای متن بدنه ریسک دارد.

### چرا رنگ هشدار از صورتی به کهربایی رفت

با آلویی شدن `primary`، کورال قدیمی (`#FFAAA6`) و تینت اصلی به هم چسبیدند:
فاصلهٔ ادراکی `#FFECEA` و `#F9EBF1` حدود **۱۴** بود — یعنی برای چشم یک رنگ.
نتیجه این می‌شد که یک قند خون خارج از محدوده دقیقاً شبیه یک چیپ معمولی
به نظر برسد. جفت جدید روی **۴۴** می‌نشیند.

در یک اپ سلامت این تزئین نیست: مادری که نمودار قندش را مرور می‌کند باید
ردیف خارج از محدوده را بدون فکر کردن ببیند.

## تایپوگرافی

فونت **IranYekan Web** در سه وزن (۴۰۰/۵۰۰/۷۰۰) استفاده می‌شود. تجاری است و
در مخزن نیست؛ فایل‌ها را در `apps/web/public/fonts/` بگذارید. بدون آن‌ها اپ
build و اجرا می‌شود و به `Vazirmatn` و فونت‌های فارسی سیستم برمی‌گردد.

با `@font-face` بارگذاری می‌شود نه `next/font/local` — چون `next/font` مسیر
را در زمان build حل می‌کند و نبودن فایل build را می‌شکند. `layout.tsx` تگ
`preload` را دستی می‌سازد، اما فقط برای وزن‌هایی که واقعاً روی دیسک‌اند.

### فاصلهٔ خطوط

فارسی به leading بیشتری از لاتین نیاز دارد: خط روی پایهٔ پایین‌تری می‌نشیند،
اعراب بالای حروف و کشیده‌ها زیرشان جمع می‌شوند، و پاراگراف متراکم با ۱٫۵
(که برای لاتین مناسب است) سخت دنبال می‌شود.

- بدنه: `line-height: 1.8` — کف راحتی روی موبایل.
- تیترها: `1.5` — تیتر دوخطی با ۱٫۸ از هم می‌پاشد.
- بلوک‌های طولانی: کلاس `leading-7` روی همان عنصر.

**هرگز به فارسی `letter-spacing` ندهید.** حروف فارسی به هم می‌چسبند و
tracking آن‌ها را از هم جدا می‌کند.

### ارقام فارسی

هیچ عددی مستقیم رندر نمی‌شود. همه از `src/lib/persian.ts` عبور می‌کنند:

```ts
toFaDigits(22)                    // '۲۲'
formatFa(1840)                    // '۱٬۸۴۰'
formatFaUnit(68.5, 'کیلوگرم')     // '۶۸٫۵ کیلوگرم'
formatFaTime(Date.now())          // '۱۹:۴۰'
formatGestational(22, 3)          // '۲۲ هفته و ۳ روز'
```

برای ورودی فرم‌ها `toEnDigits()` مسیر برگشت است — کاربر ممکن است با صفحه‌کلید
فارسی «۶۸٫۵» تایپ کند و `Number()` آن را نمی‌فهمد.

### تاریخ شمسی

`src/lib/jalali.ts` روی `date-fns-jalali` نشسته است. نکتهٔ مهم: گروه‌بندی
پیام‌ها بر مرز روز **شمسی** انجام می‌شود، نه UTC — وگرنه جداکنندهٔ «امروز» در
ساعات شب جابه‌جا می‌شود.

## RTL

`<html lang="fa-IR" dir="rtl">` و بعد هیچ استایل آینه‌ای دستی لازم نیست، به
شرطی که از ابزارهای منطقی Tailwind استفاده شود:

| به‌جای | بنویسید |
| --- | --- |
| `pl-*` / `pr-*` | `ps-*` / `pe-*` |
| `ml-*` / `mr-*` | `ms-*` / `me-*` |
| `left-*` / `right-*` | `start-*` / `end-*` |
| `border-l` / `border-r` | `border-s` / `border-e` |
| `rounded-bl` | `rounded-es` |

### دام‌هایی که خودکار حل نمی‌شوند

- **آیکون‌های جهت‌دار.** فلش «ارسال» باید به inline-end اشاره کند؛ با
  `-scale-x-100` برگردانده شده. «بازگشت» در RTL یعنی `ChevronRight`، نه `Left`.
- **حلقهٔ پیشرفت.** SVG با `rotate(-90deg) scaleX(-1)` چرخانده شده تا پیشرفت
  در جهتی که خوانندهٔ فارسی انتظار دارد پیش برود.
- **ترتیب تب‌ها.** ترتیب منبع در `BottomNav` همان ترتیب بصری راست‌به‌چپ است؛
  «خانه» سمت راست می‌نشیند، جایی که شست کاربر شروع می‌کند.
- **متن مختلط.** `dir="auto"` روی textarea کامپوزر تا پیام انگلیسی درست
  تراز شود.

## چیدمان

- **mobile-first**، حداکثر عرض محتوا `max-w-lg`.
- نوار تب پایین ثابت است؛ `.afrat-page` ارتفاعش را به‌علاوهٔ safe-area رزرو
  می‌کند تا آخرین کارت زیر نوار نرود.
- `viewport-fit=cover` در `layout.tsx` + کلاس‌های `afrat-safe-top` /
  `afrat-safe-bottom` برای notch و نوار ژست اندروید.
- حداقل هدف لمسی: کلاس `.afrat-tap` (۴۴×۴۴ پیکسل) روی هر عنصر تعاملی.

## دسترس‌پذیری

- zoom غیرفعال **نشده** (`maximumScale: 5`) — غیرفعال کردنش WCAG 1.4.4 را نقض
  می‌کند.
- هر آیکون تزئینی `aria-hidden="true"` دارد و برچسب متنی کنارش.
- تیک‌های تحویل نام دسترس‌پذیر فارسی دارند («دیده شد»، «ارسال نشد»).
- لاگ گفتگو `role="log"` + `aria-live="polite"` است.
- «در حال نوشتن…» `role="status"` است تا ادب اسکرین‌ریدر حفظ شود.
- `prefers-reduced-motion` همهٔ انیمیشن‌ها را خاموش می‌کند.
- حالت فوکوس: حلقهٔ `ring-2 ring-primary-deep` روی همه‌چیز.
